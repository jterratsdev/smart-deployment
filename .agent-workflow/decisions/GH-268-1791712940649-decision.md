# Decision GH-268: Require observed natural OWD propagation

- Status: accepted
- Owner: product_owner

## Context

User clarified that if internal OWD propagation can outlast a short wait, AC-8 should require that scenario. Existing cg-demo start/resume E2E used a forced 1 ms timeout, not measured natural lag. Workflow run wfrun-1791712922948-81751c is paused by goal-to-verification and real-product handoff checks.

## Decision

Keep naturally delayed InternalSharingModel propagation as a required AC-8 live verification. Treat the forced 1 ms timeout only as deterministic resume/checkpoint proof, not as satisfaction of AC-8. Do not mark QA coverage or release gate complete without an independently observed interval where InternalSharingModel still differs after OWD deploy, followed by expected value and dependent SharingRules deployment.

## Consequences

Design an isolated opt-in probe that records before/after InternalSharingModel with monotonic timestamps and does not induce latency artificially; if org converges immediately, report inconclusive and retain gate block. Obtain explicit human gate approval before changing criteria or retrying live mutation; preserve cg-demo Case and cleanup.
