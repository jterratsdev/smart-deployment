## Verdict (v1.0): FAIL — _(SUPERSEDED — see Re-review v1.1: PASS-WITH-FINDINGS)_

There are two major fail-open defects against the acceptance criteria:

- **F1:** the AC-004 deploy guard only covers `WaveManifestService`. `sf smart-deployment ci-publish --no-dry-run`
  builds its own core-metadata manifest, so it deploys both new types without org evidence, even when the scan
  recorded a `local-missing` error.
- **F2:** a race in gap-analysis parse verification can drop parse failures. A singular-root `MatchingRules`
  file can then be reported `supported`, which breaks AC-001.

### Regression analysis — executor early return

- **Scope of the change:** the only caller is `ci-publish` (`ci-publish.ts:73`), and only with `--no-dry-run`.
  `plan explain` builds the plan with `dryRun: true` and never executes it, so it is unaffected.
- **Warnings are not blocking:** `plan.warnings` (native OmniStudio classification, AI-eval missing `--target-org`)
  is not checked. Plans with warnings but no errors still run (covered by the existing executor tests).
- **C4 OmniStudio stays fail-closed:** blocked classifications still produce phase errors
  (`special-deployment-plan.ts:309`). That sets `plan.success` false (`:123`) and the executor now refuses the whole
  plan. Before this rework, those errors were reported but the core and other phases still ran. The new behaviour
  is strictly more fail-closed, and no blocked path is skipped silently.
- **Agentforce / AI evaluation / LWR community publish:** AI-eval precheck errors (`:251`) now also stop the whole
  run instead of only stopping later. The Agentforce publish/activate and community-publish providers emit no
  `errors`, so their behaviour is unchanged.
