# C2 Data, Analytics, and AI Metadata Catalog Research

Author: Salesforce Professional Services
Status: Research only

Vendor baseline: Salesforce Summer '26, API `67.0`

## Scope and ownership

This report owns the `crma`, `data360`, `tableau`, and `ai` setup-agents profiles. It does not claim shared platform metadata ownership. C1 owns `CustomObject`, `Flow`, and `PermissionSet`; C2 rows reference those types only as dependencies.

The comparison key is:

```text
67.0|<deployment-channel>|<vendor-type-or-artifact>
```

Rows use the fixed profile sequence `ai`, `crma`, `data360`, `tableau`, then priority and curated dependency/lifecycle sequence. Generated catalog output must instead serialize by the comparison key above. Product object API names and Data 360 DLO/DMO names are component contents, not new metadata types. Package namespaces are attributes, not catalog types.

### Capability legend

Each capability is `P` (proven), `p` (partial), `A` (absent), or `-` (not applicable):

- `D`: deterministic discovery
- `R`: semantic parsing
- `X`: dependency extraction
- `O`: deployment ordering
- `L`: deployment/publish/activation lifecycle
- `F`: deterministic fixture or test evidence

`Current support` is deliberately stricter than `src/analysis/metadata-gap-analysis-service.ts`'s binary support flag. A row is not "validated" merely because the type is present in a union, order map, or hardcoded scanner set.

## Channel boundaries

### Metadata API and source-format composites

The API `67.0` coverage baseline exposes the listed `Wave*`, `DataStreamDefinition`, `DataSource*`, `MktCalcInsightObjectDef`, and `GenAi*` candidates through Metadata API. Exposure is only transport evidence. It does not prove scanner discovery, dependency semantics, execution, scheduling, sharing, activation, or rollback.

`AiAuthoringBundle`, `GenAiPlannerBundle`, `LightningTypeBundle`, and `DataSourceBundleDefinition` are composite source artifacts. They require bundle-aware scanning; treating every nested file as an independent metadata component would create duplicates.

### Data and recipe assets

`WaveRecipe` and `WaveDataflow` definitions are Metadata API artifacts. Running them is a separate provider operation. `WaveDataset` describes dataset metadata; dataset rows/CSV payloads are data assets and must use an analytics data/import contract. Likewise, a Data 360 stream definition can be deployable while connector credentials, ingestion, identity resolution runs, segment refreshes, and activations remain provider lifecycle.

### Managed packages

Packaging coverage does not turn a metadata type into managed-package data. A candidate enters `managed-package-data` only when its installed namespace, package version, export/import mechanism, and license are explicit. C2 does not own generic package metadata. The existing `DataPackageKit*` order entries remain unproven until validated against a specific installed product.

### Tableau

Tableau workbooks, datasources, extracts, flows, projects, and permissions are Tableau Server/Cloud resources. They do not belong in a Salesforce `package.xml` and require a dedicated Tableau REST/TSC adapter with endpoint, site, project, authentication, permission, publish, refresh, and job-polling contracts.

### Provider-managed Agentforce

`AiAuthoringBundle` is the design-time source. Publishing compiles Agent Script and creates or updates runtime `Bot`, `BotVersion`, and `GenAi*` metadata. Activation is an explicit later action. The plugin correctly models publish then optional activation for authoring bundles, but it must mark generated artifacts with provenance and avoid treating them as independently authored core metadata. The CLI `Agent` selector is an aggregate pseudo type, not a catalog metadata type.

## Prioritized implementation slices

1. **P0: Capability catalog and aliases.** Replace the binary scanner/order comparison with the handoff schema, stable sort key, channel enum, per-capability evidence, explicit aliases, canonical cluster, API version, source URL, and retrieval date. Add invariants that C1 owns `CustomObject`, `Flow`, and `PermissionSet`.
2. **P0: Correct the existing AI claims.** Remove independent `BotVersion` "supported" status until it is discovered; represent `AiAuthoringBundle` as composite/provider lifecycle; retain model, field, and provider facts from prompt parsing; record generated-vs-authored planner provenance.
3. **P0: Complete AI test lifecycle.** Register and scan `AiEvaluationDefinition` and `AiTestingDefinition`, then keep Metadata API definition deployment separate from Agentforce test execution/results. Preserve both human and JSON CLI contracts.
4. **P1: Add a focused CRMA scanner family.** Register the seven listed `Wave*` metadata candidates without expanding `metadata-scanner-service.ts`; parse JSON structurally for dataset, lens, application, and recipe/dataflow dependencies. Keep data load/run/schedule/share operations in a dedicated lifecycle adapter.
5. **P1: Add a focused Data 360 metadata family.** Start with `DataSourceBundleDefinition`, `DataSourceObject`, `DataSrcDataModelFieldMap`, `MktDataTranObject`, and `DataStreamDefinition`; add calculated insights only after SQL dependency and schedule contracts exist. Gate every fixture with a licensed-org validation matrix.

## Limitations and open validation

- No `.setup-agents/references/` cache was present. Official documentation was therefore retrieved directly on 2026-07-23.
- Public Metadata Coverage proves exposure, not deploy correctness for a particular org edition, license, feature flag, namespace, or release update.
- No Salesforce org, Data 360 tenant, CRM Analytics org, Agentforce sandbox, or Tableau site was used. All org/provider validation in the table remains required.
- No repository tests were run because this assignment is research-only. Existing tests were inspected as evidence.
- `MarketSegmentDefinition`, identity resolution, activation-target, Tableau Pulse/Next, and API `67.0` Agentforce Studio lifecycle details have lower confidence until org describe and provider execution evidence exist.
- The current test fixture for `AiAuthoringBundle` omits its documented `.bundle-meta.xml` descriptor, so it proves scanner behavior against a permissive fixture, not a deployable authoring bundle.
- Unknown metadata receives order `99`; this is fallback behavior, not safe deployment evidence.
